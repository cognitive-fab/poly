## Ideas

### 1. `close()` waits for the worker pass that is running

- **Source:** the owner's serial run of v1.4 (`serial-v14-demo.txt`), 2026-10-28; release notes v1.4, known limits.
- **What was seen:** `[poly-runtime] database is not open` after `DF12.1`. `close()` clears the worker's intervals and closes the store, and a pass already running resumes against the closed store. The cut-off attempt is recovered as a lost attempt and not run again (S119), so the behaviour is correct; the line is noise.
- **Idea:** `startWorkers` keeps the promise of each running pass, and `close()` awaits them before it closes the kernel.
- **Status:** the owner asked for it in the v2.0 proposals (2026-10-28).

### 2. One preflight for openssl in the serial after-suite

- **Source:** `serial-v14.txt`, 2026-10-28.
- **What was seen:** without `openssl` on the path, the seven demo files that assemble the concierge fail 23 times with the same `spawnSync openssl ENOENT`, and the nine cases of `DF19, DF21, DF24` are never reached, so the count of tests changes with the environment (138 against 146).
- **Idea:** a check before the serial group that names runbook step 0.7 once and stops, as S116 does for the key.
- **Status:** open.

### 3. Logs a person can read whatever the shell

- **Source:** `serial-v14.txt` and `serial-v14-demo.txt`, 2026-10-28.
- **What was seen:** PowerShell's redirection wrote both logs as UTF-16, with the reporter's marks re-encoded (`Γ£ö` for a pass), so they had to be converted before they could be counted.
- **Idea:** the runbook and `npm test` write the log with `--test-reporter=spec --test-reporter-destination=<file>`, which is UTF-8 whatever the shell.
- **Status:** open.

### 4. The demo baseline's preregistered toolchain kept by digest

- **Source:** DB16 item 4a (`docs/proposals/demo-refund.md`), 2026-10-28.
- **What was seen:** `DB16.3(b)` is reported as not run on v1.4, because the repository keeps no copy of the toolchain the preregistration names (`sha256:6ee4130d...`).
- **Idea:** an archive of that workspace, stored by its digest outside the tree, so the byte comparison can run on any later version. The preregistration is not amended (the owner's ruling).
- **Status:** open.

### 5. Retry safety for compensable effects

- **Source:** release notes v1.4, known limits (order-fulfilment's charge), 2026-10-28.
- **What was seen:** PS23.5 covers irreversible effects only, so a compensable charge with an undocumented key keeps three attempts and can charge twice.
- **Idea:** belongs with proposal 3 (retry safety as an effect type); recorded here until proposal 3 is written out.
- **Status:** open; joins proposal 3.

### 6. A person's response as a named assumption of a liveness verdict

- **Source:** release notes v1.4, known limits (incident-oncall, subscription-cancel), 2026-10-28.
- **What was seen:** the person who settles an uncertain outcome is in the fair set, so the property holds only if that person acts, and the verdict says this only through the fair set.
- **Idea:** the verdict lists the people it assumes act, apart from the timers and completions, so a reader sees which part of `CLEAN` rests on a person.
- **Status:** open.

### 7. `poly lsp` in VS Code

- **Source:** the VS Code adapter (PT14, `adapters/vscode`), 2026-10-28.
- **What was seen:** the adapter colours poly but shows no diagnostics, formatting or fixes. VS Code starts a language server only from extension code (an `activate` function with `vscode-languageclient`), and an adapter holds configuration only (S167, rule 3 of the boundary check).
- **Idea:** either a ruling that lets one small, reviewed launcher file live in `adapters/vscode` (it starts `poly lsp` over stdio and nothing else), checked by the boundary check as the adapter JSON's servers are; or a generic language-client extension configured by JSON, so the adapter stays configuration only.
- **Status:** open; needs the owner's ruling on S167.

### 8. Hyphenated property names as one token

- **Source:** the VS Code adapter, tokenizing `incident-oncall.poly` with Oniguruma, 2026-10-28.
- **What was seen:** a property name such as `page-at-most-once` is coloured as words with `-` operators between them, since the grammar has no rule for the name; the parser reads it as one name by adjacency (PT2).
- **Idea:** a scope for a property's or an obligation's name after its keyword, specified in PT14 before it is added.
- **Status:** open.
